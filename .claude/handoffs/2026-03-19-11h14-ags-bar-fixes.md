## Decisions Made
- **NotificationCenter**: replaced `.as()` child binding and `<For>` with imperative `$` callback
  + module-level `_panelList` / `rebuildPanelRows()` pattern (identical to NotificationToast.tsx).
  Reason: `notifications.as(list => list.map(...))` returns an Accessor, which gnim's jsx renders as
  `[object instance wrapper...]` when used as a JSX child. `<For>` was tried but also failed
  (still rendered garbage — root cause unclear, possibly a gnim version issue).
- **WorkspaceIndicator**: replaced `createComputed`/`createBinding` visibility with imperative
  `$` callbacks + signal handlers. Then added `_focusedWsId` module-level tracker.
  Reason: `hyprland.focusedWorkspace` returns null when the active workspace loses its last
  client (even if the viewport stays on that workspace), causing `focusedId` to default to 1.
  `_focusedWsId` preserves the last non-null focused workspace ID so the active pip never
  incorrectly hides or loses its active styling.

## Failed Approaches
- `<For each={reversedNotifications}>` — imported correctly from `"ags"`, proven pattern in
  SystemTray.tsx, but still rendered garbage text in the notification panel. Root cause not
  fully diagnosed; imperative approach was used instead.
- `createComputed` + `createBinding` for WorkspacePip visibility — empirically fails to update
  button visibility; `hyprland.focusedWorkspace?.id ?? 1` with no null-guard caused pip to hide
  when workspace became empty.
