# Feature: Rice CLI Tools

<!-- SpecKit /specify layer: what and why -->
## Overview

**User Story**: As a desktop ricer, I want btop, atuin, procs, tealdeer, dust, duf, and hexyl themed and configured to match my Chrysaki wallpaper-derived palette so that every tool in my terminal feels visually cohesive.

**Problem**: Newly installed CLI tools use their default themes, breaking the visual consistency of the desktop. btop and atuin are frequently visible TUI apps that stand out against the rest of the themed environment.

**Out of Scope**:
- Tools classified as "not riceable": sd, hyperfine, tokei, gping, xh
- Runtime/dynamic theme switching (colors are generated at dev-time like all other tools in the pipeline)
- yazi (already riced -- configs exist in `yazi/`)

## Scope

### Must-Have
- **btop Chrysaki theme**: Custom `.theme` file with colors derived from `theme.css`, plus `update_colors.py` integrated into the pipeline. Done when btop launches showing Chrysaki palette colors for all UI elements.
- **btop base config**: `btop.conf` with preferred layout, update rate, and theme selection pointing to the Chrysaki theme. Done when `btop` launches with the correct theme auto-selected.
- **atuin config**: `config.toml` with preferred style (compact/full), search mode, inline vs fullscreen, and any available color settings. Done when atuin search TUI uses the configured display mode.
- **Stow integration**: Each new tool is a stow package in `~/dots/` and added to the `bootstrap.sh` stow line. Done when `stow btop atuin procs tealdeer` succeeds without errors.

### Should-Have
- **procs config**: `config.toml` with custom column order, dark color scheme, and preferred column visibility. Done when `procs` shows customized columns in dark mode.
- **tealdeer config**: `config.toml` with custom accent colors (if supported) and cache settings. Done when `tldr` uses configured display preferences.

### Nice-to-Have
- **dust alias**: Shell alias with `--bars-on-right` and preferred depth flag.
- **duf alias**: Shell alias with `--theme dark`.
- **hexyl alias**: Shell alias with `--color=always` and preferred border style.
- **Alias sourcing**: All tool aliases in a dedicated `zsh/.config/zsh/tool-aliases.zsh` file sourced from `.zshrc`.

## Technical Plan

**Affected Components**:

| Component | Action |
|:----------|:-------|
| `btop/.config/btop/btop.conf` | Create -- base config with theme selection |
| `btop/.config/btop/themes/chrysaki.theme` | Create -- Chrysaki-derived color theme |
| `btop/scripts/update_colors.py` | Create -- reads `theme.css`, emits `.theme` file |
| `atuin/.config/atuin/config.toml` | Create -- layout and behavior preferences |
| `procs/.config/procs/config.toml` | Create -- column layout and dark scheme |
| `tealdeer/.config/tealdeer/config.toml` | Create -- display preferences |
| `zsh/.config/zsh/tool-aliases.zsh` | Create -- dust/duf/hexyl aliases |
| `zsh/.zshrc` | Modify -- add `source` line for tool-aliases.zsh |
| `bootstrap.sh` (line 237-238) | Modify -- add `btop atuin procs tealdeer` to stow list |

**Data Model Changes**: None (config files only).

**API Contracts**: N/A.

**Dependencies**:
- `theme/.config/theme/theme.css` must exist (generated by `generate_theme_css.py`)
- btop, atuin, procs, tealdeer, dust, duf, hexyl must be installed (handled by `tools.sh` in bootstrap)

**Risks**:
| Risk | Likelihood | Mitigation |
|:-----|:-----------|:-----------|
| btop `.theme` format is undocumented or incompatible with hex colors | Medium | Research btop source/wiki; fall back to adapting an existing theme file as template |
| atuin has no color customization at all | Medium | Spec the layout/behavior config only; note color gap for upstream feature request |
| tealdeer color names are limited (no hex support) | Low | Use closest named colors from the available set |

## Acceptance Scenarios

```gherkin
Feature: Rice CLI Tools
  As a desktop ricer
  I want all CLI tools themed with Chrysaki colors
  So that my terminal environment is visually cohesive

  Background:
    Given the Chrysaki palette is generated in ~/.config/theme/theme.css
    And all new stow packages are stowed via "cd ~/dots && stow btop atuin procs tealdeer"

  Rule: btop must display Chrysaki theme colors

    Scenario: btop launches with Chrysaki theme
      Given btop/.config/btop/btop.conf exists with color_theme = "chrysaki"
      And btop/.config/btop/themes/chrysaki.theme contains colors derived from theme.css
      When the user runs "btop"
      Then btop displays using the Chrysaki color palette
      And background, text, graph, and border colors match the palette

    Scenario: btop theme regenerates from updated palette
      Given the Chrysaki palette has been updated (submodule bump)
      When the user runs "python3 ~/dots/btop/scripts/update_colors.py"
      Then btop/.config/btop/themes/chrysaki.theme is regenerated with new colors
      And the output file follows the btop .theme format specification

    Scenario: btop update_colors.py handles missing theme.css gracefully
      Given ~/.config/theme/theme.css does not exist
      When the user runs "python3 ~/dots/btop/scripts/update_colors.py"
      Then the script prints an error message and exits without writing

  Rule: atuin must use configured display preferences

    Scenario: atuin uses configured search style
      Given atuin/.config/atuin/config.toml exists
      When the user presses Ctrl+R to invoke atuin
      Then atuin displays in the configured style (compact or full)
      And search mode matches the configured value (fuzzy/prefix/substring)

  Rule: procs must display customized columns in dark mode

    Scenario: procs shows custom column layout
      Given procs/.config/procs/config.toml exists with column definitions
      When the user runs "procs"
      Then procs displays the configured columns in dark color scheme

  Rule: tealdeer must use configured display preferences

    Scenario: tealdeer uses custom colors
      Given tealdeer/.config/tealdeer/config.toml exists
      When the user runs "tldr ls"
      Then tealdeer displays with the configured color settings

  Rule: CLI-flag tools use preferred defaults via aliases

    Scenario Outline: Tool alias applies preferred flags
      Given zsh/.config/zsh/tool-aliases.zsh is sourced in .zshrc
      When the user runs "<alias>"
      Then the command executes as "<expanded>"

      Examples:
        | alias | expanded                         |
        | dust  | dust --bars-on-right             |
        | duf   | duf --theme dark                 |
        | hexyl | hexyl --color=always --border=bold|

  Rule: All configs are stow-managed

    Scenario: New packages stow without errors
      Given the btop, atuin, procs, and tealdeer directories exist in ~/dots/
      When the user runs "cd ~/dots && stow btop atuin procs tealdeer"
      Then all configs are symlinked to ~/.config/ without conflicts
      And bootstrap.sh stow line includes the new packages
```
